# AI業務効率化 サービスパッケージ

**業務改善コンサル・研修・伴走支援・環境設定の4本柱＋必要に応じた受託開発。外部の専門家が組織に入り、「自社だけでAIが回る状態」まで導きます。**

---

## 1. 日本企業のAI活用、今の現実

- 生成AIを「活用している」と答えた日本企業はわずか **17.3%**
- 業務プロセスに正式に組み込めている企業は **24%**
- 導入した企業でも、**「期待を上回る効果を実感」しているのはわずか10%**

> 出典：帝国データバンク 生成AIの活用状況調査（2024年）/ PwC Japan 生成AIに関する実態調査（2025年春）

**ほとんどの日本企業は、AIを導入できていないか、導入しても成果が出ていない。** これが今の現実です。

---

## 2. なぜ進まないのか？5つの壁と、私たちの解決策

### 壁1：AIを使いこなせる人がいない

AIを使いこなせる人材が社内にいない。外部採用も難しい。結局「詳しい人が1人で頑張る」状態になり、その人が抜けたらゼロに戻る。

**→ 解決策：研修 ＋ 伴走支援**

体系的な研修で全社員を底上げしつつ、専門家が継続的に伴走支援で対応させていただきます。研修で学んだことを実務に落とし込むところまで、一緒に進めます。

---

### 壁2：どこにAIを入れればいいかわからない

ツールは配った。でも現場は「便利そうだけど、自分の仕事のどこに使えるの？」で止まっている。結果、議事録の要約くらいで活用が止まる。

**→ 解決策：業務改善コンサル**

業務を一緒に見て、**「どこにAIを入れると一番効くか」** を数値で特定する。優先順位つきのロードマップを出すので、「なんとなく使う」から「ここに入れれば効く」に変わる。

---

### 壁3：セキュリティ・情報漏洩が怖い

「これAIに入れていいんだっけ？」の判断が個人任せ。逆に「怖いから全面禁止」にしてしまい、活用が進まない会社も多い。

**→ 解決策：業務改善コンサル ＋ 環境設定**

業務改善コンサルで「何をAIに入れていい／ダメか」のルールを一緒に決める。環境設定で、チーム全員が同じ環境・同じ権限設定でAIを使えるように整える。「禁止」ではなく「安全に使える環境」を用意する。

---

### 壁4：経営層・中間管理職が動けていない

トップが「AIを入れろ」と言っても、中間管理職が止めてしまう。逆に現場がやりたくても、上が理解していなくて予算が通らない。

**→ 解決策：伴走支援（専門家が継続的に入る）**

AI活用の専門家が経営層向けROI報告、中間管理職向けワークショップ、現場との日常伴走をまるっと引き受けます。**外部の専門家が毎週継続的に関わる** ことで、社内だけでは動かなかった歯車を回します。

---

### 壁5：やってみたけど定着しない

研修を1回やって「AI導入完了」にしている会社がほとんど。使い方を忘れる、新機能が出ても追いつけない、結局もとのやり方に戻る。PoCから本番に進むのは **全体の1/3だけ**。

**→ 解決策：伴走支援（3〜6ヶ月の継続支援）**

研修で終わりにせず、3〜6ヶ月間、専門家が継続的に対応させていただきます。週次定例、チャットサポート、現場の「これも自動化できない？」を都度拾って仕組みに落とす。最終ゴールは **「私たちがいなくても自走できる状態」** にすること。

## 4. サービスメニュー

### ① 業務改善コンサル —「どこにAIを入れるか見つける」

**何を解決するか**
「AIを入れたいけど、どこに入れればいいかわからない」。現場も経営も、AI活用の優先順位が見えていない状態。

**具体的にこうやる**
1. 対象部門にヒアリング（3〜5部門を並行）。現状の業務を聞き出す
2. 業務フローをマップ化し、「どの作業に何時間かかっているか」を数値で出す
3. 各業務に「AIを入れた時の削減時間 × 実現難易度」でスコアをつける
4. 優先順位つきのAI適用ロードマップを作成
5. 経営層向けに、投資と回収のROIレポートを作成
6. AI活用のルール（どんなデータを入れてよいか、どんな使い方がNGか、権限の切り分け）を一緒に設計

**主な成果物**
業務フロー診断レポート / 優先順位ロードマップ / ROI試算 / AI活用ルールガイド

**なぜ最初に必要か**
ここがブレると後工程すべてがブレる。「なんとなくAIを入れる」を避けるため、必ず最初に入れる。

---

### ② 研修 —「使える人を育てる」

**何を解決するか**
社内にAIを使いこなせる人がいない。YouTubeを見せているだけでは体系的に学べず、議事録要約で止まる。

**具体的にこうやる**
1. 組織のレベルに合わせてカリキュラムをカスタマイズ
2. 既存の動画研修ライブラリ（数十コンテンツ、ChatGPT / Claude / Gemini / Perplexity / Manus 横断）を配信
3. 部門別ワークショップで「自分の仕事のどこに使うか」を実際にやる
4. 社内トレーナーを養成し、外部に頼らず教え合える体制を作る
5. **Claude Code / Claude API 等、開発者向けの専門コースも順次拡充中**

**主な研修テーマ**
- 全社員向け：AIってそもそも何？／AIとの付き合い方／主要AIツールの使い分け／社内利用ガイドライン
- 部門別：営業・企画・バックオフィス・開発、業務別ワークショップ
- 専門：AI資料作成／画像・動画生成／AIエージェント活用／社内トレーナー養成

**主な成果物**
研修動画ライブラリ（カスタマイズ配信）／部門別ワークショップ／社内トレーナー

---

### ③ 伴走支援 —「専門家が現場に入り、定着するまで対応させていただきます」

**何を解決するか**
研修して終わりにすると定着しない。経営層・中間管理職・現場の温度差で組織が動かない。**本サービス最大の差別化ポイント。**

**具体的にこうやる**
1. AI活用の専門家が、3〜6ヶ月にわたり継続的に伴走支援で対応させていただきます
2. **チャットサポート** で日常の質問に即レスで対応
   - 例：「この議事録をAIで要約したいんだけど、どのツールで、どうやるのが一番早い？」→ その場でやり方を返信
   - 例：「お客さんへの提案書のたたきをAIに作らせたい、プロンプトどう書けばいい？」→ 使えるプロンプト例を共有
   - 例：「このExcelの集計、AIに任せたいんだけど安全？」→ データの扱い方と手順を回答
3. 週次定例で導入状況の振り返り、困りごと解消、次アクションの決定
4. 現場から出る「この業務、AIで自動化できない？」をその場で一緒にやってみせる
5. 月次で利用状況・改善提案をレポート化
6. 経営層向け報告、中間管理職向けワークショップ、社内トレーナーのメンタリング
7. AIの最新アップデート情報を整理して共有

**常駐について**
基本は「必要なときに入る」伴走スタイルです。ただし、**ご要望があれば常駐・半常駐での対応も可能** です（別途ご相談）。

**主な成果物**
専門家による伴走 / 週次定例 / チャットサポート / 月次レポート / 経営層報告

---

### ④ 環境設定 —「開発者向けAIを、チームで使える状態にする」

**何を解決するか**
Claude Code / Cursor / GitHub Copilot などの **開発者向けAI** を社内で導入したいけど、設定方法がわからない。チームごとにバラバラの環境で、誰も同じように使えない。

**具体的にこうやる（Claude Code / Cursor / GitHub Copilot の3つに対応）**

1. **インストールと初期設定**
   - 各ツールのインストール手順を整理し、チーム全員が迷わず入れられる状態にする
   - アカウント発行・ログイン・プラン選定を支援
   - 権限ルール（どこまでAIに自動実行させるか）をチームで統一

2. **IDE連携・エディタ設定**
   - VS Code / JetBrains / ターミナル、それぞれの環境で動くようセットアップ
   - チームで統一した拡張機能・設定ファイルを配布

3. **プロジェクト設定テンプレート**
   - 各プロジェクトに置く設定ファイル（CLAUDE.md など）のテンプレートを作成
   - 「このプロジェクトはこう書かせる」というルールをAIに渡す仕組みを整える

4. **実用的な使い方のセットアップ**
   - 「こういう場面ではこう使う」の具体例をチームに共有
   - プロンプトテンプレート集の整備

5. **チーム全員が同じ環境で使えるよう標準化**
   - 誰が入っても迷わない、同じ品質のAI活用ができる状態にする

**主な成果物**
Claude Code / Cursor / GitHub Copilot の導入済み環境 / IDE設定 / プロジェクト設定テンプレート / プロンプトテンプレート集 / 権限ルール

---

### ⑤ 受託開発 —「社内でできない部分は持ち帰って作る」

**何を解決するか**
伴走中に「これは社内だけでは作れない」という案件が出てくる。現場の時間が足りない、技術的に難しい、大規模すぎる、など。

**具体的にこうやる**
1. 伴走中に「社内では対応が難しい」と判断した開発案件を受託
2. 要件定義から設計・開発・納品までまるっと引き受ける
3. 納品後、社内メンバーが運用できるようにドキュメント整備と引き継ぎまで行う

**対象例**
- 特定業務向けのカスタムAIツール
- 大規模なデータ処理・分析スクリプト
- 複数システム連携の自動化パイプライン
- 社内独自の RAG・AIエージェント構築

**料金**
プレミアムプランには **月1件までの受託案件** が含まれます。月の件数を超える分、および大規模案件は別途お見積もり。

## 5. 導入の流れ（推奨：半年）

```
Phase 1             Phase 2                  Phase 3               Phase 4
2週間〜1ヶ月         1〜2ヶ月                 2〜6ヶ月              ——

業務改善コンサル     研修 ＋ 環境設定         伴走支援              自走

・業務フロー診断    ・全社員向け研修         ・専門家による伴走    ・社内トレーナーが
・優先順位決定      ・業務別ワークショップ   ・週次定例            　独り立ち
・ロードマップ作成  ・Claude Code /           ・チャットサポート    ・社内だけでAIを
・AI活用ルール設計  　Cursor / GitHub          ・月次レポート        　回せる状態へ
・ROI試算          　Copilot の環境構築       ・必要に応じて受託開発 ・新機能の取り込みが
                                                                     自律的に回る
```

**なぜ半年なのか**

AIリテラシーを組織に根付かせ、社内だけで自走できる状態まで持っていくには、最低でも3ヶ月、**しっかりやるなら半年** かかります。

- 3ヶ月では「使えるようになった」で終わってしまう。研修の熱が冷める前に卒業日が来てしまい、自走までは行かない
- 半年あれば、**研修で底上げ → 伴走で現場定着 → 社内トレーナー独り立ち** までたどり着ける
- リテラシーを仕上げながら、自走体制を作る。このプロセスに最低半年が必要です

---

## 6. 「自走できる状態」の目安

ここまでいったら、もう私たちがいなくても大丈夫、という状態：

- 社内トレーナーだけで、新メンバーへの研修ができる
- 「この業務にAI使えそう」を、現場が自分で見つけられる
- 新しい仕組みの追加・修正を、社内だけで進められる
- AIの使い方のルールが社内で運用され、定期的に見直されている
- 新機能が出たときに、社内で情報をキャッチアップできる
