# フロントエンド・UI最新（2026年3月版）

> フロントエンド技術の最新アップデートまとめ。Next.js 16、React 19.x、shadcn UI + Tailwind v4、Chrome拡張 Manifest V3 の主要変更点と実践的な使い方を整理。

## 概要

2025〜2026年にかけてフロントエンド技術は大きく進化した。Next.js 16 では Turbopack がデフォルトバンドラーになり、React Compiler が安定化。React 19.x は Server Components/Actions の安定化に加え、`use()` API や `<Activity>` コンポーネントなど新機能が多数追加された。shadcn UI は Tailwind CSS v4 対応で OKLCH カラー・`data-slot` による柔軟なスタイリングへ移行。Chrome 拡張は Manifest V2 が完全廃止され、V3 + ビルトイン AI API という新時代に入っている。

---

## 1. Next.js

### 最新バージョン（16 / 16.1）・主要変更点

#### Turbopack（安定・デフォルト化）
- Next.js 16 で `next dev` / `next build` ともに **Turbopack がデフォルトバンドラー** に昇格
- Fast Refresh が 5〜10倍高速化、ビルドは 2〜5倍高速化
- 16.1 で **ファイルシステムキャッシュ（FS Cache）** が安定化。コンパイル成果物をディスクに保存し、再起動時の開発サーバー起動が最大 14倍高速化（大規模アプリで約15秒 → 約1.1秒）
- コアパッケージが約 20MB 軽量化され、CI/CD のインストール時間も短縮

#### React Compiler 1.0（安定化）
- ビルド時の自動最適化ツールが安定版に
- コンポーネントとフックの **自動メモ化** により、手動の `useMemo` / `useCallback` が不要に
- 不要な再レンダリングを自動防止し、コードの複雑さを削減

#### DevTools MCP
- **Next.js DevTools MCP** が導入。Model Context Protocol を通じて AI エージェントがアプリケーションのコンテキスト情報にアクセス可能に
- AI エージェントが問題の診断・動作の説明・修正提案を開発ワークフロー内で直接実行
- `get_routes` ツールでアプリ内の全ルート一覧を取得可能

#### その他
- `serverExternalPackages` の手動設定がほぼ不要に
- `next upgrade` コマンドで React 依存関係と型定義を最新安定版に一括更新
- アダプターファイル内で build / bundle / deploy のライフサイクルイベントにフック可能
- 16.1 で `next dev --inspect` による Node.js デバッグが容易に
- 16.1 で Bundle Analyzer（実験的）を追加

### 使い方・移行ポイント

```bash
# アップグレード
npx next upgrade

# 開発（Turbopack がデフォルト）
npx next dev

# React Compiler を有効化（next.config.ts）
const nextConfig = {
  experimental: {
    reactCompiler: true,
  },
}
```

- Turbopack は Webpack プラグインとの互換性がないため、カスタム Webpack 設定がある場合は段階的に移行
- React Compiler は `useMemo` / `useCallback` を段階的に削除して動作確認する移行がおすすめ
- DevTools MCP は Claude Code や Cursor などの AI エディタと組み合わせて活用

## 2. React 19

### 主要変更点

#### Server Components / Server Actions（安定化）
- Server Components がビルド時またはリクエスト時にサーバー側でレンダリング
- クライアントに送る JavaScript を削減し、初回読み込みを高速化
- Server Actions で `"use server"` ディレクティブを使ったサーバー側ミューテーションが可能
- Server Components がデフォルト。クライアント側の状態管理やフックを使う場合は `"use client"` を明示

#### `use()` API
- レンダリング中に Promise やコンテキストを読み取る新 API
- `use(promise)` で React が Promise 解決まで Suspend
- ループ・条件分岐・早期リターン内でも呼び出し可能（従来のフックの制約なし）

#### 新フック
- **`useActionState`**: アクション中の pending 状態を自動追跡。結果と pending ステータスを返す
- **`useFormStatus`**: 子コンポーネントから親フォームの状態にアクセス（prop drilling 不要）
- **`useOptimistic`**: 非同期データ変更時に楽観的 UI 更新を実現

#### React 19.1（2025年3月）
- **Owner Stack**: コンポーネントがどこからレンダリングされたかを追跡する開発専用機能。デバッグやエラーオーバーレイの強化に活用
- Suspense の機能強化（クライアント・サーバー・ハイドレーション各環境での改善）

#### React 19.2（2025年10月）
- **`<Activity>` コンポーネント**: コンポーネントの表示/非表示を管理しつつ状態を保持。`mode="hidden"` でコンポーネントを生かしたまま非表示にし、更新をアイドル時まで遅延
- **`useEffectEvent` フック**: Effect 内で安定したイベントハンドラを定義可能

### 使い方・移行ポイント

```tsx
// Server Component（デフォルト）
async function UserProfile({ id }: { id: string }) {
  const user = await fetchUser(id);
  return <div>{user.name}</div>;
}

// use() API
function Comments({ commentsPromise }: { commentsPromise: Promise<Comment[]> }) {
  const comments = use(commentsPromise);
  return comments.map(c => <p key={c.id}>{c.text}</p>);
}

// Activity コンポーネント（React 19.2）
<Activity mode={isVisible ? "visible" : "hidden"}>
  <ExpensiveComponent />
</Activity>
```

- Server Components では `useState` / `useEffect` は使えない。インタラクティブ要素は `"use client"` で分離
- `use()` は既存の `useEffect` + `useState` パターンでのデータ取得を大幅に簡素化
- `<Activity>` はタブ切り替え UI やプリフェッチで威力を発揮

## 3. shadcn UI + Tailwind CSS v4

### 主要変更点

#### @theme（CSS ベース設定）
- `tailwind.config.js` / `tailwind.config.ts` が不要に。CSS ファイル内の `@theme` ディレクティブで設定
- `@theme inline` でテーマ変数をインラインで定義

#### OKLCH カラースペース
- HSL カラーが **OKLCH** に変換。知覚的に均一なカラースペースで、明度・彩度・色相の操作がより予測しやすい
- Tailwind v4 のデフォルトカラーパレット全体が OKLCH に置換

#### data-slot 属性
- すべてのプリミティブ要素に `data-slot` 属性が付与
- 外部からのスタイリングやカスタマイズがセレクタベースで容易に

#### tw-animate-css
- `tailwindcss-animate` は非推奨化。後継の `tw-animate-css` が Tailwind v4 をサポート
- `@plugin 'tailwindcss-animate'` → `@import "tw-animate-css"` に移行

#### その他
- `new-york` スタイルが統合 `radix-ui` パッケージを採用。個別の `@radix-ui/react-*` が不要に
- ブロック（login, signup, sidebar, dashboard）が Radix と Base UI の両バリアントで提供
- CLI がプロジェクト設定に応じて適切なバリアントを自動選択

### 使い方・移行ポイント

```css
/* app/globals.css */
@import "tailwindcss";
@import "tw-animate-css";
@import "shadcn/tailwind.css";

@custom-variant dark (&:is(.dark *));

@theme inline {
  --color-background: oklch(1 0 0);
  --color-foreground: oklch(0.145 0.017 285.823);
  --color-primary: oklch(0.205 0.042 265.755);
  /* ... */
}
```

```bash
# 初期セットアップ
npx shadcn@latest init

# コンポーネント追加
npx shadcn@latest add button card sidebar
```

- 既存の Tailwind v3 + React 18 プロジェクトはそのまま動作（破壊的変更なし）
- 新規プロジェクトでは Tailwind v4 + OKLCH での構築を推奨
- `data-slot` によりコンポーネントの外部スタイリングが柔軟に。デザインシステムとの統合が容易

## 4. Chrome拡張 Manifest V3

### 主要変更点

#### Service Worker 化
- 永続的なバックグラウンドページが廃止され、**Service Worker** に置換
- Service Worker はアイドル時に終了するため、メモリ効率が向上
- 状態の永続化には `chrome.storage` API の使用が必須

#### declarativeNetRequest
- ブロッキング `webRequest` API が `declarativeNetRequest` に置換
- 宣言的なルールベースでリクエストを制御
- 厳格な Content Security Policy によりリモートホストコードの実行が禁止

#### Manifest V2 廃止
- 2026年時点で Manifest V2 拡張は Chrome で動作しなくなった
- 新規提出・既存拡張すべてが Manifest V3 必須

#### ビルトイン AI API（Chrome Built-in AI）
- Chrome にネイティブの AI 機能が搭載。**Gemini Nano** がデバイス上でローカル実行
- 主要 API:
  - **Prompt API**: 自然言語プロンプトを送信するテキスト生成インターフェース。マルチモーダル対応
  - **Summarizer API**: テキスト要約を生成（文章・段落・箇条書きなど複数形式対応、Chrome 138〜）
  - **Writer / Rewriter API**: AI による文章作成支援・校正・文法修正・言い換え
  - **Translator API**: 翻訳と言語検出
  - **Proofreader API**: 校正機能
- 対応環境: Windows 10/11、macOS 13+、Linux、ChromeOS（Chromebook Plus）
- モバイル版 Chrome は未対応

### 使い方・移行ポイント

```json
// manifest.json（V3）
{
  "manifest_version": 3,
  "name": "My Extension",
  "version": "1.0",
  "background": {
    "service_worker": "background.js"
  },
  "permissions": ["storage", "activeTab"]
}
```

```javascript
// Chrome Built-in AI: Prompt API の使用例
const session = await self.ai.languageModel.create({
  systemPrompt: "You are a helpful assistant."
});
const result = await session.prompt("Summarize this text...");

// Summarizer API
const summarizer = await self.ai.summarizer.create({
  type: "key-points",
  length: "short"
});
const summary = await summarizer.summarize(longText);
```

- V2 → V3 移行: バックグラウンドスクリプトを Service Worker に書き換え、状態管理を `chrome.storage` に移行
- Service Worker の終了に備え、`chrome.alarms` でタイマー処理を管理
- ビルトイン AI API はサーバーレスで AI 機能を実装可能。APIキー不要・プライバシー保護・レイテンシ削減のメリット
- Content Script で AI 処理を行う拡張設計パターンが増加（サマライザー、ライティングアシスタントなど）
