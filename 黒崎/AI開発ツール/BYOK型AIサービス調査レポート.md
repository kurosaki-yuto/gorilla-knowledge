# BYOK型 AI SaaS 調査レポート（詳細版）
> APIをユーザー持ちにしている法人向けAI SaaSの事例まとめ

**作成日：2026年2月26日**

---

## 前提：BYOKとは

**BYOK（Bring Your Own Key）** = ユーザーが自分のAPIキー（OpenAI・Anthropic・Google等）を持ち込んで使うモデル。SaaS事業者はプラットフォーム利用料のみ課金し、AI計算費用はユーザーが直接AIプロバイダーに支払う。

## 1. Cursor（Anysphere）

### ツール概要
VS Codeベースの **AIコーディングIDE**。コード補完・チャット・Agent機能を統合。開発者がAIとペアプログラミングする体験を提供。

### 数字で見る成長

| 指標 | 数値 |
|------|------|
| ARR | **$5億超**（2025年11月時点。$1億→$5億が約10ヶ月） |
| 有料顧客数 | 360,000+（法人含む） |
| DAU | 100万人超 |
| Fortune 500導入率 | 25%以上 |
| 評価額 | $293億（2025年11月） |
| 調達額 | $23億 |
| チーム規模 | 40〜60名（1人あたり売上$167万〜$250万） |

### ビジネスモデル

**サブスクリプション＋BYOK併用型**

| プラン | 価格 | 内容 |
|--------|------|------|
| Free | $0 | 基本機能＋制限付きAIリクエスト |
| Pro | $20/月 | 無制限Chat/Edit＋Agent機能 |
| Business | $40/ユーザー/月 | SSO・チーム管理・Admin API・利用分析 |
| Enterprise | カスタム | SCIM・監査ログ・専任サポート |

BYOKは **全プラン（Freeを含む）** で利用可能。これが重要で、「まず無料で自分のキーで使わせて、プロダクト体験で引き込む」設計になっている。

ただし、**Agent機能やEdit機能はCursor独自のファインチューニングモデルを使っており、BYOKでは使えない**。つまりBYOKは「入り口」で、コア機能を使うにはサブスクが必要という設計。

### ターゲット

**メインターゲット：ソフトウェアエンジニア個人 → ボトムアップで法人へ**

- 個人開発者がまず自分で使い始める（Free or Pro）
- 「生産性が上がった」と社内で広める
- チーム → 部署 → 全社導入へエスカレーション
- OpenAI・Shopify・Midjourney・Instacart・Coinbaseなどのテック企業エンジニアが早期に個人採用
- Coinbaseは全社100%採用に到達

### ユーザーが「APIキーを入れよう」と思うまでの導線

```
1. 開発者がCursorを無料でインストール（VS Codeから移行コスト低）
2. 無料枠のAIリクエストを使い切る
3. 「Proに課金するか？」 or 「自分のOpenAIキーを入れるか？」の選択肢が出る
4. 既にOpenAI APIキーを持っている開発者は、まずBYOKで使い続ける
5. Agent・Edit等のCursor独自機能が使いたくなる → サブスクへ移行
6. 法人では「自社のAzure OpenAI契約を使いたい」というCIOの要望 → Business BYOKで全社展開
```

**ポイント：BYOKは「課金までの心理的ハードルを下げるフック」として設計されている。** ゴールはサブスク課金で、BYOKはあくまで入り口。

### マーケティング

- **広告費ほぼゼロ**のPLG（Product-Led Growth）
- 開発者のTwitter/X・Hacker News・YouTubeでの口コミが主力
- 「Cursor使ったら戻れない」系のバイラル投稿が拡散
- 個人→チーム→法人のボトムアップセールスが自然に発生
- エンタープライズセールスチームは小規模で、大型案件のみ対応

### なぜこのビジネスモデルにしたか

- **開発者はコスト意識が高い** → まずBYOKで「無料で使える」体験を提供し、プロダクト体験でロックイン
- **Agent/Edit機能を独自モデル依存にすることで、BYOK→サブスクの転換を設計**
- API費用を事業者側が負担すると、DAU100万人規模では破綻する
- 法人にとっては「既存のAzure OpenAI契約を使える＝追加のセキュリティ審査不要」が最大の訴求力

## 2. GitHub Copilot（Microsoft / GitHub）

### ツール概要
GitHubが提供する **AIコーディングアシスタント**。VS Code・JetBrains・Eclipse・Xcode等の主要IDEで動作。コード補完・Copilot Chat・PR レビュー・Agent機能を持つ。

### 数字で見る成長

| 指標 | 数値 |
|------|------|
| ARR | **$3億+**（2024年推定） |
| 利用者数 | 150万人+（有料ユーザー） |
| 企業導入数 | 77,000社超（Fortune 500の半数以上） |
| 親会社 | Microsoft（時価総額$3兆超） |

### ビジネスモデル

**サブスクリプション主体 ＋ BYOKを後追い追加**

| プラン | 価格 | 内容 |
|--------|------|------|
| Free | $0 | 月2,000回の補完＋50チャット |
| Pro | $10/月 | 無制限補完＋チャット |
| Business | $19/ユーザー/月 | チーム管理・ポリシー制御 |
| Enterprise | $39/ユーザー/月 | SSO・SCIM・監査ログ・カスタムモデル |

**2025年11月：BYOK（パブリックプレビュー）を追加。Enterprise/Businessプラン限定。**

対応プロバイダー：Anthropic・OpenAI・Microsoft Foundry・xAI・AWS Bedrock・Google AI Studio・OpenAI互換API

### ターゲット

**メインターゲット：GitHub Enterpriseを既に契約している大企業の開発チーム**

- GitHubを全社導入している企業（Fortune 500の大半）
- 既にAzure OpenAI・AWS Bedrock等の法人契約がある企業
- CIO/VPofEngが「AI基盤を統一したい」と考えている組織
- セキュリティ・コンプライアンス要件が厳しい金融・ヘルスケア企業

### ユーザーが「APIキーを入れよう」と思うまでの導線

```
1. GitHub Enterprise管理者がCopilot Enterprise ($39/ユーザー/月)を契約
2. 社内エンジニアがCopilotを使い始める（GitHubの標準AIモデルで）
3. 「自社のAzure OpenAI契約のほうがレート制限が高い」「Fine-tunedモデルを使いたい」
4. → Enterprise管理画面から BYOK設定
   - Settings > AI controls > Custom models > Add API key
   - プロバイダー選択 → キー貼り付け → 利用可能モデルが自動フェッチ
   - 「全組織に許可」or「組織ごとに許可」を選択
5. 各開発者がIDE内でモデルを切り替えてBYOKモデルを利用開始
```

**ポイント：「既にGitHubを使っている企業」のCopilot有料化が先にあり、その上でBYOKは「もっとAIを活用する追加レバー」として設計。** 新規顧客獲得ではなく、既存法人顧客のARPU向上・満足度向上が目的。

### マーケティング

- **GitHubユーザーベース1億人超**へのクロスセルが主力
- GitHub UniverseなどのイベントでBYOK発表
- Microsoft Azureとのバンドル販売（企業がAzure契約するとCopilotもついてくる）
- エンタープライズセールスチームによる大企業向け直販

### なぜBYOKを追加したか

- **Cursor等の競合がBYOKで急成長** → 既存顧客がCursorに流出するリスクへの対抗
- 大企業のCIOから「MicrosoftとOpenAI両方に払うのは嫌。自社のAI予算で統一させろ」という要望
- Azure OpenAIの大口契約をCopilot経由でも使えるようにすることで、**Microsoftエコシステム全体のロックイン強化**
- 「Fine-tunedモデルを使いたい」という高度な法人ニーズへの対応

## 3. Dify.ai

### ツール概要
**LLMアプリ開発プラットフォーム**。チャットボット・AIエージェント・RAGシステム・ワークフローをノーコード/ローコードで構築できる。OSSで公開されており、SaaS版とセルフホスト版の両方を提供。

### 数字で見る成長

| 指標 | 数値 |
|------|------|
| GitHubスター | 55,000+（2025年時点） |
| 作成アプリ数 | 130,000+（クラウド版のみ） |
| 資金調達 | $430万（シードラウンド） |
| チーム規模 | 約12名 |
| 設立 | 2023年3月 |

### ビジネスモデル

**オープンソース + SaaS + エンタープライズ（三層モデル）**

| プラン | 価格 | 内容 |
|--------|------|------|
| Community（OSS） | 無料 | セルフホスト・全機能 |
| Cloud Sandbox | 無料 | 200回AIコール/月 |
| Cloud Professional | $59/月 | 5,000回AIコール/月・チーム機能 |
| Enterprise | カスタム | セルフホスト＋サポート・SSO・無制限メンバー |

**全プランでBYOK**：ユーザーは自分のOpenAI/Anthropic/Google等のAPIキーを設定して使う。Dify自体がAI計算費用を負担することは一切ない。

### ターゲット

**メインターゲット：社内AIアプリを内製したいが、開発リソースが足りない企業のIT部門**

- 非エンジニアでもAIアプリを作りたい事業部門のDX推進担当
- 金融・医療・官公庁（データを外部に出せない → セルフホスト必須）
- AIスタートアップ（プロトタイプ〜MVP開発の時短ツールとして）
- SIer・コンサル（顧客向けAIアプリの受託開発基盤として）

### ユーザーが「APIキーを入れよう」と思うまでの導線

```
1. 「社内でAIチャットボット/エージェントを作りたい」というニーズ発生
2. Difyを発見（GitHub・Qiita・技術ブログ等でOSSとして話題）
3. まずCloud Sandboxで無料トライアル → 200回制限にすぐ当たる
4. 「自社のOpenAI APIキーを入れればもっと使える」と気づく
5. Difyの管理画面 > Models Provider設定からAPIキーを入力
6. GPT-4・Claude・Gemini等を自由に使えるようになる
7. 本格運用 → セルフホスト版をKubernetesで社内デプロイ
   （データが一切外に出ないことがセキュリティ審査で通る理由になる）
8. エンタープライズ契約でサポート・SSO・監査ログを追加
```

**ポイント：「まずOSSで無料体験 → APIキーを入れて本格利用 → セルフホストで社内展開 → エンタープライズ契約」という4段階のアップセルファネルが設計されている。** APIキーを入れるタイミングは「ステップ4」で、これは無料枠の制限に当たった直後。

### マーケティング

- **GitHub OSSでバイラル拡散**（Star数55,000+のパワー）
- 技術ブログ・Qiita・Hacker News・YouTube解説動画
- 「フルスクラッチ開発の1/10のコスト・1/10の時間でAIアプリが作れる」
- 中国市場では WeChat・Bilibili等でも拡散
- セルフホストオプションを武器に「データ主権」を訴求 → 規制業種の法人が安心して導入

### なぜこのビジネスモデルにしたか

- 12名の小さなチームでは、AIモデルの計算費用を負担したら即座に赤字になる
- OSSにすることで開発者コミュニティが**勝手に翻訳・解説・プラグイン開発してくれる**（マーケティングコストほぼゼロ）
- 企業のセキュリティ審査は「データがどこを通るか」が最大の論点 → セルフホスト＋BYOKなら「一切外部に出ない」と言い切れる
- プラットフォームの価値は「使いやすいUI・ワークフロー・統合機能」であり、AI計算そのものではない → API費用を負担する理由がない

## 4. n8n

### ツール概要
**AIワークフロー自動化プラットフォーム**。ノーコードでAPIやアプリを接続し、業務を自動化するツール。2024年以降AIノード（OpenAI・Anthropic等）を積極的に統合し、AIエージェント構築プラットフォームへ進化中。

### 数字で見る成長

| 指標 | 数値 |
|------|------|
| ユーザー数 | 200,000+ |
| 法人顧客数 | 3,000社超 |
| 売上成長率 | **前年比10倍**（2024年） |
| ユーザー成長率 | 前年比6倍（2024年） |
| 評価額 | **$25億**（2025年10月） |
| 総調達額 | $2.4億 |
| 投資家 | Accel、NVentures（NVIDIA）、Highland Europe |
| チーム規模 | 100名超 |

### ビジネスモデル

**フェアコードOSS + セルフホスト + クラウドSaaS（実行回数課金）**

| プラン | 価格 | 内容 |
|--------|------|------|
| Community（OSS） | 無料 | セルフホスト・無制限ワークフロー |
| Starter | €20/月 | クラウド・2,500回実行/月 |
| Pro | €50/月 | 10,000回実行/月 |
| Business | €667/月 | セルフホスト・40,000回実行/月・SSO・SAML |
| Enterprise | カスタム | 専用サポート・無制限 |

**BYOKの位置づけ：AIノードを使う際に、ユーザーが自分のAPIキーを「クレデンシャル」として登録する形式**。n8n自体がAI費用を負担することはない。全てのAI関連処理はユーザーのキーで実行される。

### ターゲット

**メインターゲット：IT部門・DevOps・業務オペレーション担当者**

主要法人顧客の事例：
- **Vodafone UK**：サイバーセキュリティのSOAR基盤として33ワークフローを運用
- **StepStone Group**：200以上のミッションクリティカルなワークフロー、API統合を25倍高速化
- **Delivery Hero**：IT Opsワークフロー1つで月200時間削減
- **Musixmatch**：4ヶ月でエンジニアリング47日分の工数を削減

使うユーザー像：
- 業務プロセスの自動化を任されたIT部門の中堅社員
- DevOpsエンジニア（インシデント検知・アラート自動化）
- カスタマーサポートチーム（チケット自動振り分け・AI応答）
- 営業企画（CRM連携・リードスコアリング自動化）

### ユーザーが「APIキーを入れよう」と思うまでの導線

```
1. 「業務を自動化したい」ニーズでn8nを発見（Zapierの代替として検索）
2. 最初はメール通知・Slack連携・CRM同期等の「AI不要なワークフロー」から入る
3. 「AIで要約させたい」「AIで自動分類したい」という要望が出る
4. n8nのAIノード（OpenAI / Anthropic / Gemini等）をワークフローに追加
5. 「このAIノードを使うにはAPIキーを設定してください」とUI上で案内される
6. Credentials管理画面 → OpenAI/Anthropicを選択 → APIキーを貼り付け → 自動検証
7. ワークフロー内でAIが動作開始
8. 本格運用 → セルフホスト＋Enterprise契約で社内展開
```

**ポイント：ユーザーは最初「ワークフロー自動化ツール」として入ってくる。AIは後付けの機能拡張として出会う。** APIキーを入れるのは「業務フロー内でAIを使いたくなった瞬間」で、n8nの導入動機とAPIキー入力は別のタイミング。これが他のAI SaaSとの大きな違い。

### マーケティング

- **Zapier/Make.comの代替**として検索流入が主力（SEO強い）
- 「セルフホストできるワークフロー自動化」で差別化
- GitHubコミュニティ（フェアコード＝基本無料で使える）
- Vodafone・Delivery Heroなどの法人事例を前面に出したエンタープライズセールス
- NVIDIA Venturesの出資が「AIプラットフォームとしての信頼性」を裏書

### なぜこのビジネスモデルにしたか

- n8nの本質は「ワークフロー自動化」であり、AIは接続先の一つに過ぎない → AI費用を自社で負担する理由がそもそもない
- ワークフロー実行回数で課金するモデルなので、AIの計算費用とプラットフォーム費用が明確に分離されている
- セルフホストを武器にすることで「全データが社内に閉じる」を保証 → 法人のセキュリティ審査をパスしやすい
- ZapierがAI機能を内製費用込みで提供しているのに対し、n8nは「AI費用はユーザー持ち」にすることで**価格競争力を維持**

## 5. TypingMind

### ツール概要
**ChatGPTの上位互換UI**。OpenAI・Anthropic・Google等のAPIキーを入力し、高機能なチャットインターフェースで利用できるツール。法人向けには「TypingMind Custom」としてホワイトラベル・チーム管理機能を提供。

### 数字で見る成長

| 指標 | 数値 |
|------|------|
| MAU | 141,000+ |
| 法人チーム数 | 1,048+ |
| 年間売上 | $100万（2024年11月に到達、ローンチから20ヶ月） |
| 収益構造 | 一括購入50%・サブスク50%（法人サブスクの比率が急拡大中） |
| チーム規模 | 少人数（創業者Tony Dinh氏が個人開発者出身） |
| 設立 | 2023年3月 |

### ビジネスモデル

**完全BYOK型 ＋ プラットフォーム利用料**

| プラン | 価格 | 内容 |
|--------|------|------|
| 個人版（買い切り） | $79一括 | 個人利用・自分のAPIキーで全モデル利用 |
| TypingMind Custom Starter | $99/月 | 5席・チーム管理・カスタムブランド |
| Custom Growth | $199/月 | 5席＋拡張機能 |
| Custom Professional | $299/月 | 50席対応 |
| Custom Business | $7,000〜/年 | ボリュームディスカウント（最低$4/ユーザー/月） |

**重要な特徴：TypingMind自体はAI費用を一切負担しない。100%BYOK。** ユーザーは自分のAPIキーを使い、プラットフォームの使いやすさ・チーム管理・AI Agent機能に対して課金する。

### ターゲット

**メインターゲット：AIを全社展開したい中小〜中堅企業のIT管理者**

主要法人顧客の事例：
- **InnoGames**：57個のAIエージェントを月次運用、157名がSSO連携、月1,000万トークン利用
- **Atomic Object**：社員の80%が利用、ソフトウェア開発の加速
- **Mention Me**：マーケティング・カスタマーサポートでの活用

使うユーザー像：
- 「全社員にAIを使わせたいが、ChatGPT Enterpriseは高すぎる」と思っている情シス担当
- 「各部署ごとにカスタムAIエージェントを作りたい」PM・マネージャー
- リセラーパートナー（自社ブランドでAIチャットを顧客に提供したいSIer・コンサル）

### ユーザーが「APIキーを入れよう」と思うまでの導線

**パターンA：個人ユーザーの場合**
```
1. 「ChatGPT Plusの$20/月が高い」or「GPT-4のレート制限が嫌」で検索
2. TypingMindを発見（「自分のAPIキーで無制限に使える」が刺さる）
3. $79一括購入 or 無料トライアル
4. 初回起動時に「APIキーを入力してください」と案内（設定必須）
5. OpenAI/Anthropic等のキーを貼り付け → 即使用開始
6. ChatGPTより高機能（プロンプトライブラリ・プラグイン・マルチモデル切替）で満足
7. 「チームでも使いたい」→ TypingMind Customへアップセル
```

**パターンB：法人管理者の場合**
```
1. 「全社員にAIを使わせたい。ChatGPT Enterpriseは$60/月/人で高すぎる」
2. TypingMind Customを発見
3. 管理者がAdmin Panel > APIキー設定 で会社のOpenAI/Anthropicキーを一括設定
4. SSO連携で全社員がログイン → 社員はAPIキーを知らないまま使える
5. 管理者はダッシュボードで利用量・コストをモニタリング
6. 部署ごとにカスタムAIエージェント（営業用・CS用・開発用等）を構築
```

**ポイント：個人版は「初回起動時にAPIキー入力が必須」=BYOKが前提の設計。法人版は「管理者が一括設定し、社員はキーを意識せず使う」設計。** この二層構造がBYOKモデルとしては非常にうまく設計されている。

### マーケティング

- **「ChatGPT Plusより安く、制限なく使える」** というシンプルな訴求
- IndieHackers・Product Hunt等のインディー開発者コミュニティでバイラル
- Tony Dinh氏のTwitter/X発信（50,000フォロワー超）がマーケチャネル
- **リセラープログラム**：SIer・コンサル会社が自社ブランドで再販 → B2B販路の拡大
- 「ChatGPT Enterprise ($60/月/人) vs TypingMind Custom ($4/月/人〜)」の価格比較が強い

### なぜこのビジネスモデルにしたか

- 個人開発者出身（Tony Dinh）の少人数チーム → API費用を負担する体力がない
- ChatGPT/Claude等の公式UIの「不便さ」を解決するのが本質的な価値 → UIとワークフローに課金する
- BYOKにすることで「利用量無制限」が実現 → ChatGPT PlusやEnterpriseとの価格差が明確な差別化になる
- 法人向けは「管理者がキーを一括管理、社員はキーを知らない」設計にすることで、BYOKの煩雑さを排除

## addnessへの示唆

### BYOKモデルが成立する条件

1. **プラットフォーム自体に独自価値がある**（UI・ワークフロー・チーム管理・セキュリティ等、AIモデルの計算以外のところ）
2. **法人のセキュリティ要件に応えられる**（データが外に出ない・自社の契約キーで使える）
3. **アップセルの導線が設計されている**（Free → BYOK → サブスク → Enterprise）
4. **AI費用を事業者が持たないことで、価格競争力を維持できる**（ChatGPT Enterpriseの1/10の価格等）

### 法人にガッツリ売るためのBYOK設計パターン

- **Cursor型**：BYOKで体験させ → 独自機能で有料転換（サブスク収益が主力）
- **Dify/TypingMind型**：100% BYOKでAI費用ゼロ → プラットフォーム料で収益化（低価格訴求が可能）
- **GitHub型**：既存エコシステムの上にBYOKを追加（クロスセル・ロックイン強化）
- **n8n型**：AI以外が本体で、AIは追加機能としてBYOK（ユーザー獲得とAI課金のタイミングが分離）
