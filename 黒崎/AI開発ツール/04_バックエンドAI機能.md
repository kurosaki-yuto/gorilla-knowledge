# バックエンドAI機能（2026年3月版）

> AI機能を支えるバックエンドサービスの最新状況

## 概要

AI搭載アプリケーションのバックエンドでは、ベクトル検索・LLMキャッシュ・ワークフロー自動化・エージェント構築が主要テーマとなっている。本ドキュメントでは、Supabase（BaaS＋ベクトルDB）、Upstash（サーバーレスRedis/Vector）、Dify（ノーコードAIエージェントビルダー）、n8n（ワークフロー自動化）の4ツールについて、2026年3月時点の最新情報をまとめる。

---

## 1. Supabase

### 最新バージョン・主要変更点

#### pgvector
- PostgreSQL拡張としてベクトル類似度検索を提供。`CREATE EXTENSION IF NOT EXISTS vector;` で有効化
- HNSW（Hierarchical Navigable Small World）とIVFFlatの2種類のインデックスをサポート
- DiskANN（pgvectorscale）が2026年の大きな進化点。インデックスをSSD（NVMe）上に配置でき、RAMコストを大幅削減

#### Vector Buckets
- pgvectorとは別の耐久性重視のベクトルストレージレイヤー
- 数百万ベクトル規模、S3相当の耐久性、RAG・セマンティック検索向き
- pgvector（低レイテンシ・小〜中規模）とVector Buckets（大規模・アーカイブ用途）を使い分け可能
- Foreign Data Wrapper経由でPostgresから両方をクエリ可能
- 自動インデックス最適化により、大規模データでも高速検索を維持

#### ハイブリッド検索
- tsvector（キーワード検索）+ pgvector（セマンティック検索）を単一SQLで組み合わせ可能
- メタデータフィルタも同一クエリ内で適用できるため、従来のフルテキスト検索とベクトル検索を統合

### 使い方・導入手順

1. **pgvector有効化**
   ```sql
   CREATE EXTENSION IF NOT EXISTS vector;
   ```

2. **テーブル作成**
   ```sql
   CREATE TABLE documents (
     id SERIAL PRIMARY KEY,
     content TEXT,
     embedding VECTOR(1536)
   );
   ```

3. **インデックス作成（HNSW推奨）**
   ```sql
   CREATE INDEX ON documents
     USING hnsw (embedding vector_cosine_ops);
   ```

4. **Vector Buckets**はダッシュボードまたはJavaScript SDKから作成。バケット＋インデックスを設定後、メタデータ付きでベクトルを格納

5. **ハイブリッド検索**はRPCファンクションとして実装し、tsvectorスコアとpgvectorスコアを重み付けして統合

## 2. Upstash

### 最新バージョン・主要変更点

#### Redis LLMキャッシュ
- サーバーレスRedisでLLMレスポンスをキャッシュ。エッジ/サーバーレス関数と相性が良い
- LangChain統合により、既存のLLMパイプラインにRedisキャッシュを簡単に追加可能

#### Vector（セマンティックキャッシュ）
- サーバーレスベクトルDBで、セマンティック類似度に基づくキャッシュを実現
- `@upstash/semantic-cache` パッケージで、意味的に類似したクエリに対してキャッシュヒットを返す
- `minProximity`パラメータ（0〜1）でキャッシュヒットの閾値を調整
- プリセットの埋め込みモデルを選択可能（低レイテンシ優先: `bge-small-en-v1.5`、精度優先: より大きなモデル）

#### QStash
- サーバーレスメッセージング＆スケジューリング基盤
- LLM API呼び出しをネイティブサポート。リトライ・コールバック・バッチ処理を自動化
- QStashがAPI呼び出しの仲介役となり、配信保証と自動リトライを提供

#### Workflow
- QStash上に構築されたワークフローエンジン
- 複数ステップのAIパイプラインをサーバーレスで構築可能
- インフラ管理不要でリトライ・エラーハンドリングを自動化

### 使い方・導入手順

1. **Upstashコンソール**でRedis/Vectorデータベースを作成
2. **環境変数**を設定（`UPSTASH_VECTOR_REST_URL`, `UPSTASH_VECTOR_REST_TOKEN`）
3. **セマンティックキャッシュの例**:
   ```typescript
   import { SemanticCache } from "@upstash/semantic-cache";
   import { Index } from "@upstash/vector";

   const cache = new SemanticCache({
     index: new Index(),
     minProximity: 0.95,
   });

   // キャッシュにセット
   await cache.set("capital of France", "Paris");
   // セマンティック検索でヒット
   const result = await cache.get("what is the capital of France?");
   ```

4. **QStash LLM呼び出し**: QStashダッシュボードからLLM APIエンドポイントを設定し、リトライポリシーを定義

### 料金

| サービス | 無料枠 | 有料プラン |
|----------|--------|------------|
| Redis | 256MB、10Kコマンド/日 | PAYG: $0.20/100Kリクエスト、固定: $10/月〜 |

- Vercel Marketplace経由での統合も可能

## 3. Dify

### 最新バージョン・主要変更点

2026年2月時点で **v1.14.0** まで到達。GitHubスター数は急速に増加中。

#### Agent Node
- ワークフロー内でLLMに自律的なツール制御を付与
- 事前にステップを計画するのではなく、動的に推論しながらツールを呼び出す
- トークン使用量の正確な追跡機能（入力/出力トークンを分離計算）
- 構造化された使用量データを後続ノードで活用し、コスト制御の自動化が可能

#### MCP双方向サポート（v1.6.0）
- 任意のMCPサーバーをDifyから直接呼び出し可能
- Difyのエージェント/ワークフローをMCPサーバーとして他のクライアントに公開可能

#### マルチモーダルナレッジベース
- テキストと画像を統一的なセマンティック空間に格納
- マルチモーダルRAGとビジョン対応推論を実現

#### その他の進化
- **Summary Index**: チャンクにサマリーを付与し、関連コンテンツをまとめて返却
- **Triggers**: スケジュール実行、イベント駆動自動化、プラグイン統合を統一
- **Human Input Node**: ワークフロー内に人間のレビューステップをネイティブに埋め込み
- **非同期DB書き込み**: ワークフロー実行エンジンの高速化。並列ブランチの実行時間を最長ブランチの所要時間に近づけた

#### Supabaseプラグイン
- DifyからSupabaseをベクトルストアとして直接利用可能（※要確認：プラグインマーケットプレイスで提供状況を確認）

### 使い方・導入手順

1. **セルフホスト**（推奨）:
   ```bash
   git clone https://github.com/langgenius/dify.git
   cd dify/docker
   docker compose up -d
   ```
   - Docker Compose一発で起動。LLM APIキーを設定すれば利用開始

2. **クラウド版**: dify.ai でアカウント作成、Sandbox（無料）から開始

3. **Agent Nodeの利用**:
   - ワークフローエディタでAgent Nodeを追加
   - 接続するツール（API、データベース、MCPサーバーなど）を設定
   - LLMが動的にツールを選択・実行

### 料金

## 4. n8n

### 最新バージョン・主要変更点

#### HITL（Human-in-the-Loop：人間承認フロー）
- AIエージェントがツール実行前に人間の承認を要求する仕組み
- エージェントからツールへの接続に「Add human review step」を設定
- 承認リクエストはSlack、Telegram、n8n Chatなど任意のチャネルに送信
- ツールが使おうとしているパラメータを表示し、承認/拒否を選択
- 高リスク操作（メッセージ送信、レコード変更、データ削除）に選択的に適用可能

#### Chat Node
- Chat Trigger + AI Agentの組み合わせでチャットボットを構築
- 「Send a message and wait for response」アクションでエージェントが人間に確認を求めるフローを実装
- LangChain JavaScript基盤で、OpenAI・Anthropic・Google Gemini・Ollama等を統合

#### 400+統合
- CRM、データベース、メッセージング、決済、REST API等、422以上のアプリ/サービスと統合
- AI Agent Nodeから全統合をツールとして利用可能

#### マルチエージェントオーケストレーション
- 複数のAIエージェントを連携させるワークフローパターンが2026年に普及
- エージェント間のタスク委譲、結果の集約を視覚的に設計

#### メモリ管理
- 4種類のメモリタイプ: セッション内メモリ、ウィンドウメモリ、サマリーメモリ、永続DBメモリ
- 用途に応じて適切なメモリ戦略を選択

### 使い方・導入手順

1. **セルフホスト**（Docker）:
   ```bash
   docker run -it --rm \
     --name n8n \
     -p 5678:5678 \
     -v n8n_data:/home/node/.n8n \
     docker.n8n.io/n8nio/n8n
   ```

2. **AIエージェント構築の基本フロー**:
   - Chat Trigger → AI Agent Node → LLM Sub-Node（GPT-4, Claude等）
   - ツールとしてHTTP Request、データベース、外部APIを接続
   - メモリノードを追加して会話履歴を保持

3. **HITL設定**:
   - AI AgentからToolへの接続線で「+」をクリック
   - 「Add human review step」を選択
   - 承認チャネル（Slack等）と承認者を設定

## 組み合わせパターン

### パターン1: Supabase + Dify
- Supabase pgvectorをDifyのベクトルストアとして利用
- Dify Agent Nodeで自律的なRAGアプリを構築
- 適用: 社内ナレッジベース、カスタマーサポートBot

### パターン2: Upstash + n8n
- n8n AI AgentのレスポンスをUpstash Redisでキャッシュ
- QStashでLLM API呼び出しのリトライ・バッチ処理を管理
- 適用: 大量リクエスト処理、コスト最適化が必要なシナリオ

### パターン3: Supabase + Upstash + n8n
- Supabaseをデータ永続化＋ベクトル検索に利用
- Upstashでセマンティックキャッシュ＆メッセージキュー
- n8nでワークフロー全体をオーケストレーション
- 適用: 本格的なAIプロダクション環境
