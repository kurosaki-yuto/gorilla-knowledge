## 1. addness-step（SaaS型オンボーディング管理）

### 現状の技術スタック

| カテゴリ | 技術 |
|---------|------|
| フレームワーク | Next.js 16.1.6 |
| UI | React 19.2.3 + shadcn UI (v3.8.5) + Tailwind CSS v4 + tw-animate-css |
| バックエンド | Supabase (SSR + supabase-js v2.98) |
| フォーム | React Hook Form + Zod v4 |
| データ可視化 | @tanstack/react-table + @xyflow/react |
| LINE連携 | @line/bot-sdk v10 |
| テーマ | next-themes |

### 適用可能なツール・技術

#### AI SDK v6 + Supabase Vector → AIチャット機能

**目的**: ユーザーのオンボーディング質問にAIが回答するチャット機能の追加

**導入ステップ**:
1. `@ai-sdk/react` と `@ai-sdk/anthropic`（または `@ai-sdk/openai`）をインストール
2. Supabase で `CREATE EXTENSION IF NOT EXISTS vector;` を実行し、pgvector を有効化
3. オンボーディングナレッジ（FAQ・手順書）のembeddingを生成し、Supabase に保存
4. Route Handler（`app/api/chat/route.ts`）で AI SDK の `generateText` + ツール呼び出しを実装
5. フロントエンドに `useChat` フックでチャットUIを追加（shadcn UIのコンポーネントを活用）

```typescript
// app/api/chat/route.ts のイメージ
import { generateText } from 'ai';
import { anthropic } from '@ai-sdk/anthropic';
import { createClient } from '@supabase/supabase-js';

export async function POST(req: Request) {
  const { messages } = await req.json();
  const result = await generateText({
    model: anthropic('claude-sonnet-4-6'),
    messages,
    tools: { searchKnowledge: /* Supabase vector検索ツール */ },
  });
  return result.toDataStreamResponse();
}
```

#### React Compiler の活用

- Next.js 16.1.6 ではすでにReact Compiler 1.0が利用可能
- `next.config.ts` で `experimental: { reactCompiler: true }` を追加するだけ
- 手動の `useMemo` / `useCallback` を削除でき、コードがシンプルに

#### Tailwind v4 + shadcn の最新機能

- 既にTailwind v4を使用中。`@theme` ディレクティブでデザイントークンを一元管理
- shadcn v3 の `data-slot` でコンポーネントのスタイリング柔軟性を活用

### 次やるべきことリスト

1. [ ] Supabase に pgvector 拡張を追加し、ナレッジベーステーブルを作成
2. [ ] AI SDK v6 をインストールし、チャットAPIルートを実装
3. [ ] `useChat` を使ったチャットUIコンポーネントを作成
4. [ ] React Compiler を有効化してパフォーマンスを自動最適化
5. [ ] DevTools MCP を設定し、AI支援の開発ワークフローを構築

## 2. addness-line-hub（LINE自動応答ハブ）

### 現状の技術スタック

| カテゴリ | 技術 |
|---------|------|
| フレームワーク | Next.js 15 (Turbopack) |
| UI | React 19 |
| LINE連携 | @line/bot-sdk v9 |
| キャッシュ | Upstash Redis |
| GitHub連携 | @octokit/rest |

### 適用可能なツール・技術

#### Claude Code Agent Teams → マルチエージェント開発

**目的**: 複雑な機能追加・バグ修正をClaude Code Agent Teamsで並列処理

**導入ステップ**:
1. `.claude/` ディレクトリにプロジェクト固有の設定を配置
2. `.claude/agents/` にLINE応答ロジック専用のエージェント定義を作成
3. `.claude/skills/` にLINE Bot SDK のベストプラクティスをスキルとして記述
4. Agent Teams で「API設計」「テスト作成」「ドキュメント更新」を並列実行

```
# .claude/agents/line-bot-agent.md の例
## Role
LINE Bot機能の実装・修正を担当するエージェント

## Skills
- @skills/line-bot-sdk.md
- @skills/upstash-redis.md

## Rules
- Webhook エンドポイントは app/api/webhook/route.ts に統一
- Redis キャッシュのTTLは1時間をデフォルトとする
```

#### Next.js 16 へのアップグレード

- Next.js 15 → 16 へアップグレードし、Turbopack のデフォルト化・FS Cache を活用
- `@line/bot-sdk` も v9 → v10 にアップデート（APIの互換性確認が必要）
- React Compiler 1.0 の有効化

#### Upstash Workflow でLINE応答の非同期処理

- 長時間処理（AI回答生成、外部API呼び出し等）を Upstash Workflow で非同期化
- QStash による遅延メッセージ送信の実装

### 次やるべきことリスト

1. [ ] Next.js 15 → 16 にアップグレード
2. [ ] @line/bot-sdk v9 → v10 にアップデート
3. [ ] `.claude/agents/` と `.claude/skills/` を整備
4. [ ] Upstash Workflow を導入し、非同期メッセージ処理を実装
5. [ ] Claude Code Agent Teams でリファクタリングを実施

## 3. twitter-bookmark-sync（Xブックマーク自動同期）

### 現状の技術スタック

| カテゴリ | 技術 |
|---------|------|
| Chrome拡張 | Manifest V3（Content Script + Popup） |
| サーバー | Node.js（バニラ、依存パッケージなし） |
| データ形式 | Markdown ファイル |

### 適用可能なツール・技術

#### AI自動分類

**目的**: ブックマークしたツイートを自動でカテゴリ分類・タグ付け

**導入ステップ**:
1. サーバー側に AI SDK（`ai` + `@ai-sdk/anthropic`）を追加
2. ブックマーク保存時に Haiku モデルでカテゴリ・タグを自動生成
3. Markdown のフロントマターにカテゴリ・タグを追記

```javascript
// 分類ロジックのイメージ
import { generateObject } from 'ai';
import { anthropic } from '@ai-sdk/anthropic';
import { z } from 'zod';

const result = await generateObject({
  model: anthropic('claude-haiku-4-5-20251001'),
  schema: z.object({
    category: z.enum(['AI開発', 'フロントエンド', 'バックエンド', 'ビジネス', 'その他']),
    tags: z.array(z.string()).max(5),
    summary: z.string().max(100),
  }),
  prompt: `以下のツイートを分類してください:\n${tweetContent}`,
});
```

#### Upstash Redis でキャッシュ・重複排除

**目的**: 同じブックマークの二重保存防止 + API呼び出しの削減

**導入ステップ**:
1. `@upstash/redis` をサーバーに追加
2. ブックマークIDをRedisにキャッシュし、重複チェック
3. AI分類結果もキャッシュし、同一ツイートの再分類を防止

#### Chrome拡張のAI統合

- Chrome の Built-in AI API（Prompt API / Summarization API）が利用可能になった場合、オフラインでの簡易分類が可能に
- 現時点ではサーバーサイドAIが実用的

### 次やるべきことリスト

1. [ ] サーバー側に AI SDK を導入し、自動分類機能を実装
2. [ ] Upstash Redis でブックマークIDのキャッシュ・重複排除を実装
3. [ ] Markdown フロントマターにカテゴリ・タグ・要約を自動追記
4. [ ] 分類結果をもとにインデックスファイル（カテゴリ別一覧）を自動生成
5. [ ] Chrome拡張のUI改善（分類結果のプレビュー表示）

## 4. 求人自動化（自動スカウト・パイプライン管理）

### 現状の技術スタック

| カテゴリ | 技術 |
|---------|------|
| 言語 | Python 3.10+ |
| スクレイピング | Playwright + BeautifulSoup4 |
| パイプライン管理 | Airtable / Notion |
| 通知 | Slack Webhook |
| スケジュール | schedule ライブラリ + Cron |

### 適用可能なツール・技術

#### n8n HITL（Human-in-the-Loop）でスカウト承認フロー

**目的**: 自動収集した案件を人間が「やる/やらない」を判断するフローの構築

**導入ステップ**:
1. n8n をセルフホスト（Docker）で立ち上げ
2. 現在のPythonスクレイピングの結果を n8n Webhook で受信
3. AI Agent Node で案件のスコアリング・要約を実行
4. HITL ノードで担当者に Slack/メール通知 → 承認/却下
5. 承認された案件を Airtable/Notion に自動登録

```
# n8n ワークフロー構成
Webhook受信 → AI Agent(案件スコアリング) → HITL(承認待ち) → Airtable登録 → Slack通知
```

#### Dify Agent Node でスコアリング強化

**目的**: 案件の適合度を AI で自動スコアリング

**導入ステップ**:
1. Dify をセルフホスト（Docker Compose）で立ち上げ
2. 「案件スコアリングAgent」を作成:
   - 入力: 案件タイトル、説明文、報酬、稼働条件
   - ナレッジ: 自分のスキルセット・希望条件をアップロード
   - 出力: スコア（1-10）、理由、推奨アクション
3. Dify の API を既存の Python スクリプトから呼び出し
4. Supabase プラグインで結果を永続化

#### Python → n8n への段階的移行

- 現在のPythonスクリプトを一気に置き換えるのではなく、n8n と並行運用
- スクレイピング部分はPlaywrightの方が柔軟なのでPythonに残す
- パイプライン管理・通知・承認フローを n8n に移行

### 次やるべきことリスト

1. [ ] n8n を Docker でセルフホスト立ち上げ
2. [ ] Dify を Docker Compose でセルフホスト立ち上げ
3. [ ] Dify で案件スコアリングAgent を作成・テスト
4. [ ] n8n で HITL 承認ワークフローを構築
5. [ ] 既存 Python スクリプトから n8n Webhook への送信を実装
6. [ ] Airtable/Notion への自動登録フローを n8n に移行
