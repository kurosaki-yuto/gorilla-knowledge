# AI導入・業務自動化 サービスパッケージ

---

## 1. 日本企業のAI導入、実態はこうなっている

まず数字を見てください。

| 指標 | 日本 | 米国 | 中国 |
|------|------|------|------|
| 個人のAI利用率 | **26.7%** | 68.8% | 81.2% |
| 業務での具体的活用率（メール・議事録等） | **32.1%** | 75.0% | 78.0% |
| AI活用方針を定めている企業 | **49.7%** | 84.8% | 92.8% |

> 出典：総務省 令和7年版 情報通信白書（2025年）

生成AIを「活用している」と答えた企業は **17.3%**。業務プロセスに正式に組み込んでいる企業に至っては **24%**で、調査対象5カ国中で最低です。

> 出典：帝国データバンク（2024年）/ PwC Japan 5カ国比較調査（2025年春）

さらに厳しいのは、導入した企業でも **「期待を上回る効果を実感」しているのはわずか10%**。米国の45%と比べると、4倍以上の差がついています。

> 出典：PwC Japan 生成AIに関する実態調査（2025年春）

つまり、**ほとんどの日本企業はAIを導入できていないか、導入しても成果が出ていない**。これが今の現実です。

## 2. なぜ導入できないのか？5つの壁と、私たちの解決策

### 壁1：人材・ノウハウがない（企業の54〜62%が指摘）

> 「AI運用の人材・ノウハウ不足」を課題に挙げた企業は **54.1%**（帝国データバンク）。IPAの調査では **62.4%** に達し、前年の49.7%から急増しています。

AIを使いこなせる人がいない。外から採用しようにも、AI人材は市場で取り合い。結局「詳しい人が1人で頑張る」状態になり、その人が抜けたらゼロに戻る。

**→ 本サービスでの解決策**

研修で「人を育てる」。しかも1人だけじゃなく、チーム全体・全社員を対象にした体系的なカリキュラムで底上げする。最終的には社内トレーナーを養成して、外部に頼らず社内で教え合える体制を作る。

---

### 壁2：どの業務にAIを使えばいいかわからない（39〜54%）

> 「活用すべき業務の不明確さ」を挙げた企業は **39.1%**（帝国データバンク）。「効果的な活用方法がわからない」は総務省調査でも導入懸念のトップに位置しています。

AIツールのアカウントは配った。でも現場の反応は「便利そうだけど、自分の仕事のどこに使えるの？」。結果、議事録の要約くらいで止まっている。

**→ 本サービスでの解決策**

「業務フロー分析」から入る。お客さんの業務を一緒に見て、「ここにAIを入れると効果が大きい」というポイントを特定する。研修も「AIの使い方」だけじゃなく、「自分の仕事のどこに当てはめるか」を考えるワークショップ形式にする。

---

### 壁3：セキュリティ・情報漏洩が怖い（約7割が懸念）

> 「社内情報の漏洩等のセキュリティリスク」は、総務省調査で導入懸念の上位に常にランクイン。「コンプライアンス・企業文化・風習における脅威」を感じる企業は前回比 **+23ポイント急増して44%** に達しています。

> 出典：PwC Japan（2025年春）

「これAIに入れていいんだっけ？」の判断基準がないまま、現場が勝手に使っている。逆に「怖いから全面禁止」にしてしまい、活用が進まない会社も多い。

**→ 本サービスでの解決策**

「禁止」じゃなく「ルールを作る」。AIに入力していいデータ・ダメなデータの基準、権限管理、監査ログの仕組みを一緒に設計する。研修でもセキュリティの考え方を全社員に教える。安心して使える環境を整えることで、活用を加速させる。

---

### 壁4：経営層が旗を振れていない・中間管理職が壁になっている

> 「社長直轄」「CoE組織」が関与している割合は日本企業では他国の半分以下。PwC調査では **中間管理職がAI活用推進のカギ** とされており、ここが動かないと現場も動かない構造が指摘されています。

トップが「AIを入れろ」と言っても、中間管理職が「うちの部署には関係ない」と止めてしまう。逆に現場がやりたくても、上が理解していなくて予算が通らない。

**→ 本サービスでの解決策**

研修を「現場だけ」にしない。経営層向けのROI報告、中間管理職向けの業務別ワークショップを組み合わせて、組織の上から下まで巻き込む。伴走支援では月次レポートで効果を数値化し、経営層が意思決定しやすい状態を作る。

---

### 壁5：やってみたけど定着しない（PoCの2/3が本番に進めていない）

> PoCから本番稼働に移行できているプロジェクトは全体の **約3分の1のみ**。残り2/3はPoC段階で終わっています。全社的導入に至っている企業は **21.9%** にとどまります。

> 出典：IPA DX動向調査 / AI経営総合研究所

研修を1回やって「AI導入完了」にしている会社がほとんど。使い方を忘れる、新機能が出ても追いつけない、結局もとのやり方に戻る。

**→ 本サービスでの解決策**

だから「伴走支援」がある。研修で終わりにしない。3〜6ヶ月間、週次で定例を回し、Slackで日常の質問に答え、現場で出てきた「これも自動化できない？」を都度拾って開発する。最終ゴールは「私たちがいなくても自走できる状態」にすること。

## 3. サービス全体像

**「AIって何？」から「業務が自動で回る」まで、まるごと面倒を見る。**

```
STEP 1          STEP 2           STEP 3          STEP 4          STEP 5
AIを知る    →   使ってみる   →   業務に当てる →   仕組みを作る →  自走する

「AIって何？」    実際に手を       自分の仕事の     自動化の基盤     社内だけで
 から始める      動かしてみる     どこに使えるか    を構築する      回せる状態へ
                                 を見つける
```

| | AI研修 | 受託開発 | 伴走支援 |
|--|--------|---------|---------|
| **一言で言うと** | 使い方を教える | 仕組みを作る | 定着するまで一緒に走る |
| **解決する壁** | 壁1（人材不足）壁2（活用先不明） | 壁2（活用先不明）壁3（セキュリティ） | 壁4（組織の壁）壁5（定着しない） |
| **ゴール** | 全社員がAIを安全に業務で使える | AIが社内システムとつながった状態 | 社内だけで回せる自走体制 |

## 4. サービスメニュー

### A. AI研修 —「使い方を教える」

| 研修名 | 誰向け？ | 何をやるか | 時間 |
|--------|---------|-----------|------|
| **AIってそもそも何？** | 全社員 | AIの仕組み、できること・できないこと、身近な活用例、「賢い検索エンジン」との違い | 半日 |
| **AIとの付き合い方** | 全社員 | 「任せる・伝える・見極める・確かめる」のフレームワーク、プロンプトの基本、セキュリティの考え方 | 半日 |
| **Claudeの基本操作** | 全社員 | Claudeの使い方、ファイル添付、リサーチ、資料作成、共同作業 | 半日 |
| **業務別AI活用ワークショップ** | 部門ごと | 営業・企画・バックオフィス・開発、それぞれの業務で「どこにAIを当てはめるか」を実際にやってみる | 1日 |
| **Claude Code 基礎** | エンジニア | エージェント型AIの概念、基本ワークフロー、IDE統合 | 1日 |
| **Claude Code 実践** | エンジニア | GitHub連携、自動コードレビュー、思考モード、実プロジェクトハンズオン | 1日 |
| **MCP・サブエージェント** | エンジニア / リード | 社内ツールとAIの接続、MCPサーバー構築、サブエージェント設計、スキルの共有 | 1日 |
| **Claude API開発** | テックリード | API認証、プロンプト設計、RAG構築、エージェント設計、クラウド連携 | 1〜2日 |
| **社内トレーナー養成** | 研修担当者 | AIリテラシーの教え方、研修設計、よくある質問への対応 | 1日 |

### B. 受託開発 —「仕組みを作る」

| やること | こんな課題に効く | 作るもの |
|---------|----------------|---------|
| **業務フロー分析・AI適用設計** | 「どこにAIを入れればいいかわからない」 | 業務フローマップ、AI適用ポイント一覧、優先順位つきロードマップ |
| **社内MCPサーバー開発** | 「Slack / Jira / 社内DBをAIから直接使いたい」 | MCPサーバー、接続設定、運用マニュアル |
| **社内ナレッジ検索（RAG）** | 「社内ドキュメントをAIに検索・回答させたい」 | RAGパイプライン、ベクトルDB、API、管理画面 |
| **AIコードレビュー基盤** | 「PRが出たら自動でAIレビューを走らせたい」 | GitHub Actions連携、レビュールール、運用ガイド |
| **業務自動化エージェント** | 「定型業務をまるごとAIに任せたい」 | カスタムエージェント、サブエージェント設計、運用基盤 |
| **AI活用ルール・ガバナンス設計** | 「AI利用のルールとチェック体制を整えたい」 | 利用ポリシー、権限設計、監査ログ設計、ガイドライン文書 |
| **スキルライブラリ構築** | 「チームごとにバラバラな使い方を標準化したい」 | テンプレート集、配布設定、管理ガイド |

### C. 伴走支援 —「定着するまで一緒に走る」

| 支援内容 | やること |
|---------|---------|
| **週次定例** | 導入状況の振り返り、現場の困りごと解消、次のアクション決め |
| **Slackサポート** | 日常的な質問・トラブルへの即レス対応 |
| **業務適用コンサルティング** | 「この業務にAI使えない？」を一緒に考えて、やり方を設計する |
| **月次レポート** | 利用状況の可視化、KPI計測、改善提案 |
| **追加開発** | 伴走中に出てきた「これも欲しい」を都度開発 |
| **新機能キャッチアップ** | AIの最新アップデート情報を整理して共有 |
| **社内トレーナーのメンタリング** | トレーナーが自信を持って教えられるようになるまでサポート |
| **経営層向け報告** | ROIレポート作成、導入効果の数値化、次フェーズの提案 |

## 5. 導入の流れ

```
Phase 1（1ヶ月目）         Phase 2（2〜3ヶ月目）       Phase 3（4〜6ヶ月目）

「知る・触る」              「業務で使う」               「自走する」

・AIってそもそも何？研修     ・業務別ワークショップ       ・全社展開
・Claudeの基本操作研修       ・実案件でのハンズオン       ・社内トレーナーが独り立ち
・エンジニア向け基礎研修     ・業務フロー分析            ・ベストプラクティス集完成
・セキュリティルール策定     ・MCPサーバー等の開発        ・KPIを自分たちで回せる
・パイロットチーム選定       ・伴走支援スタート          ・卒業判定 → 自走へ
```

---

## 6. 「自走できる状態」のチェックリスト

ここまでいったら、もう私たちがいなくても大丈夫、という基準：

- [ ] 社内トレーナーだけで新メンバーへの研修ができる
- [ ] 「この業務にAI使えそう」を現場が自分で見つけられる
- [ ] 仕組みの追加・修正が社内で完結する
- [ ] KPIを自分たちで計測・改善サイクルを回せる
- [ ] 新機能のキャッチアップが自律的に回っている
- [ ] セキュリティルールが運用され、定期的に見直されている

## 7. パッケージ例

### ライト —「まず試したい」
- **研修：** 「AIってそもそも何？」+「Claudeの基本操作」+「Claude Code基礎」
- **開発：** なし
- **伴走：** Slackサポート 1ヶ月
- **期間：** 1ヶ月 / 〜5名

### スタンダード —「チームで本格的にやりたい」
- **研修：** AIリテラシー全般 + エンジニア向け基礎〜実践 + 業務別ワークショップ
- **開発：** 業務フロー分析 + MCPサーバー1本 + ガバナンス設計
- **伴走：** 3ヶ月（週次定例 + Slack + 月次レポート）
- **期間：** 3ヶ月 / 〜20名

### プレミアム —「全社でAI組織に変わりたい」
- **研修：** 全コースからカスタマイズ + 社内トレーナー養成
- **開発：** 業務フロー分析 + MCPサーバー複数本 + RAG + AIコードレビュー基盤 + ガバナンス設計
- **伴走：** 6ヶ月（週次定例 + Slack + 月次レポート + 経営層報告 + 追加開発枠）
- **期間：** 6ヶ月 / 人数相談
